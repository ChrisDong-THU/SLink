# 架构与网络约束

## 数据路径

```text
热点设备 → Windows Mobile Hotspot / ICS
        → SLink Wintun adapter → HEV Socks5 Tunnel
        → 127.0.0.1:SOCKS5 → 上游服务
```

WPF 主进程管理界面、托盘、异步任务和健康状态。通过 Windows PowerShell 5.1 执行 `native/network.ps1`，使用 JSON 传递状态。网络脚本集中管理系统网络变更，探测实现单独放在 `network-probes.ps1`。

## 应用边界

- `MainWindow` 协调异步操作与视图更新；`ConnectionPresentation` 和 `ConnectionStage` 只计算按钮动作、状态、无障碍名称及阶段显示，不执行网络操作。按钮渲染与点击共用动作判断。
- `PrimaryButtonMotion` 独立管理动画时钟，轮询不会重启动画。忙碌外环在窗口可见时持续运行；装饰动画遵循 Windows 动画偏好，隐藏或最小化停止所有动画。
- `NativeBridge` 限定网络命令与超时，使用每次请求独立的原子 JSON 结果文件。命令进程退出并返回有效结果才算完成，独立运行的转发进程不会通过继承标准输出句柄阻塞结果读取；结果缺失、格式错误或异常退出都不能视为成功。
- `ProcessRunner` 管理短期辅助进程、输出读取、超时和取消，不接管网络脚本登记的长期转发进程。`Core` 保留配置、数据解析、日志和本机代理检测。

启动、恢复与修复成功结果携带 PID、网卡 GUID 和检查时间。主窗口在最后一次状态检查结束后一起发布状态和健康结果；身份一致且结果有效时复用已完成的链路检查，身份改变则重新检测。

## 路由与 DNS

HEV 与 Wintun 创建独立网卡。网卡使用低优先级默认路由，保留原有首选路由与系统代理，不更改 Clash 配置。映射 DNS 使用 `198.19.0.0/16` 地址池，将域名交由 SOCKS5 代理解析。本会话的 `.qobuz.com` DNS 定向规则防止热点回退到原网络解析。

## 会话归属与清理

网络操作串行执行。会话记录包含进程路径、PID、创建时间与网卡 GUID；停止、退出、升级和恢复仅处理身份匹配的资源。清理失败保留恢复记录，避免把未知资源当成本程序创建的资源删除。配置通过临时文件和原子替换写入。

不要在自动排错中删除会话文件、终止所有同名进程或重置所有网卡。任何恢复路径都必须继续验证所有权，且有超时边界。

## 健康检查与修复

启动和运行中检查热点 DNS、绑定网卡的 HTTPS 与 Qobuz Connect WebSocket 握手。传输失败时通过原 SOCKS5 复测，用于区分转发故障与上游异常。

结果必须匹配当前 PID 和网卡 GUID，并在有效时间窗口内；重复、陈旧或未来结果不能累计故障。连续三轮确认热点 DNS 异常或热点关闭后才请求修复，间隔至少五分钟，同一会话最多两次。上游异常不触发热点重建；修复保留代理引擎与已有地址映射。

## 本地数据

数据位于 `%LOCALAPPDATA%\SLink`，包括设置、设备偏好、会话记录、`app.log`、`network.log`、最近健康结果 `health.json` 与轮转历史 `health-history.jsonl`。卸载保留用户设置。日志可能包含设备和网络标识，分享前应检查并脱敏。
